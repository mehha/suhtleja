# Boards (`/koduhaldus`, `/boards/[id]`, and `/kodu`)

## Scope
- Route UI: `src/app/(frontend)/koduhaldus/page.tsx`, shared management UI in `src/app/(frontend)/boards/*`
- Home pinned listing and ordering: `src/app/(frontend)/kodu/*`
- Collection: `src/collections/Boards/index.ts`
- Related managed game collection: `src/collections/ConnectDotsPuzzles/index.ts`

## Behavior Rules
- `/tegevused` is a legacy alias and only redirects to `/koduhaldus`. Keep it for existing links; do not add logic there.
- Access model:
  - Auth required for boards routes.
  - Parent mode is required for `/koduhaldus` management route.
  - Owner/admin boundaries must be preserved.
  - Board content editing (layout, cells, compounds) is owner-only.
  - Admin may view all boards but must not edit another user's board content.
  - Admin may still manage board-level shared visibility as a moderation/oversight action.
  - Server actions that modify a board must enforce document-level permissions.
  - The board pages (`/boards/[id]`, `/boards/[id]/edit`) load the board with `findBoardForUser` (`src/utilities/findBoardForUser.ts`): the collection's read access decides, so another user's private board is not found. The board goes to the browser, so it carries no user documents: the owner stays an id and depth 1 fills the cells' media but not their uploaders (a populated user has the email, PIN hash and Stripe ids). Tested in `tests/int/access-control.int.spec.ts`.
  - The editor's `renameBoard` updates with `overrideAccess: false` and the current user, so only the owner can rename a board.
  - `/koduhaldus` is also the parent-mode management surface for connect-dots puzzles.
  - `/koduhaldus` loads every board and game (`pagination: false`; Payload's default stops at 10), with only the fields its lists show (`select`) and owners only as name, email and role (`populate`), for the same reason: the page goes to the browser.
- `/koduhaldus` switches (`boards/ActionSwitch.tsx`): `Koduvaade` for boards and games, and `Nähtavus` for admins on boards, are switches with the state next to them (`Koduvaates` / `Peidetud`, `Kõigile nähtav` / `Ainult omanikule`).
  - A switch flips at once (`useOptimistic`) and saves in the background. The actions (`togglePinned`, `togglePuzzlePinned`, `toggleVisibility`) return an `ActionResult` instead of redirecting and revalidate `/koduhaldus` and `/kodu`, so the switch settles on the saved value; the success toast comes when the save returns, and a failed save flips the switch back with an error toast.
  - An admin sees another user's private board with a disabled home switch: its home view is the owner's choice.
- Board fields:
  - `name` is required.
  - `owner` is relationship to `users` and should default to current user on create.
  - `pinned` controls visibility on `/kodu`.
  - `visibleToAllUsers` allows admins to expose a board to every authenticated user without transferring ownership.
  - `order` controls pinned ordering.
  - A cell's `linkBoard` is the id of a board the card opens (a number, not a relationship, so loading a board never loads the boards it opens).
  - `ttsCache` stores pregenerated speech metadata for saved cell labels, saved compound speech forms and the word forms the board's sentences can need (see "Word form rules").
- Board cell editor rules:
  - The cell modal has one picture search instead of tabs (`/next/image-search`, see `symbols-ai.md`). It starts with the card's text when the modal opens and searches while typing (350 ms debounce). Results come in groups: `Minu pildid` (the member's own uploads and saved AI pictures), `Suhtleja kogu` (the shared library: media in a folder, including shared AI pictures) and one group per symbol bank. `Kõik allikad` (the default) shows ARASAAC and Mulberry; the source select narrows the search to one group or bank, and OpenMoji (`OpenMoji (emojid)`) only appears when chosen. An empty search lists the newest own and library pictures. Mulberry has English labels only, so an Estonian word reaches it through Groq's English terms; ARASAAC uses them only when nothing else was found. A bank group found through those terms says which terms it used. The licence line under the results names only the banks shown.
  - Picture bank: when the search is empty (source `Kõik allikad` or `Suhtleja kogu`) and the bank has categories (`/next/picture-bank`), the modal shows `Minu viimased pildid` and a grid of category cards (name and cover picture) instead of the newest library pictures. A category card opens that category's pictures, with `← Kategooriad` back to the grid. The `Kategooriad` button next to the source select clears the search and opens the grid. Typing a search leaves the bank view.
  - Choosing a picture while the card's text is empty sets the text to the picture's word (its alt text), so a card picked from the bank speaks.
  - Word class (`sõnaliik`): each card has an optional `wordClass` (`src/utilities/wordClass.ts`), shown as the card's border colour after the modified Fitzgerald key: people and pronouns yellow, actions green, descriptions blue, things orange, places brown, question words purple, social words pink, other words grey.
    - The cell modal's `Sõnaliik` select (with `Määramata`) suggests the class from the card's text while it is typed (`/next/word-class`, 350 ms debounce, see `symbols-ai.md`), and the hint under it says when the class was suggested. The preview takes the colour.
    - A card without a class gets a suggestion when the modal opens. A class saved on the card stays until the text changes; a word with a known class then replaces it, an unknown word keeps it. Once the parent picks in the select, the text no longer changes the class in that modal.
    - Bulk add asks `/next/word-class` once for all its cards and saves the classes with them.
    - The board setting `extra.wordClassColors` (`Lisaseaded` → `Sõnaliigi värvid sees/väljas`, on by default) shows or hides the colours on the board, in the editor and in the phrase bar. Turning it off keeps the saved classes.
  - While the board's word forms are on, the cell modal shows how a verb card is said (`Lauses: mina jooksen · tema jookseb · ei jookse · eile jooksin`), a place card (`Lauses: lähen kooli · olen koolis`) or a noun card (`Lauses: tahan õuna · kaks õuna`), or, for a verb class card in -ma that the verb list doesn't have, that Suhtleja doesn't conjugate it yet.
  - The cell modal's `Avab tahvli` select sets the board the card opens: `Ei ava, ütleb sõna` or one of the boards the member can read (own and shared, not this one; the edit page loads them with `overrideAccess: false`). A saved board the member can no longer read shows as `Tahvel pole enam saadaval`, so it can be cleared.
  - `Lae üles` and `Loo AI-ga` are buttons under the results. An upload becomes one of `Minu pildid`.
  - Choosing a picture (search result, AI picture, upload) must not clear the current `Tekst` input before the user presses save.
  - A picture chosen in the cell modal (symbol, AI image, upload, media) is only staged: the preview and a ring on the chosen tile show it, and it replaces the card's picture only on `Salvesta`. `Tühista` or closing the modal keeps the old picture. (An upload is already in the media collection by then.)
  - `Loo AI-ga` opens a panel that generates 4 pictograms with `/next/symbol-generate` (see `symbols-ai.md`) and shows the member's remaining monthly generations. When the search already found own or library pictures, the panel points to them first. It also says that a saved AI picture joins the shared library unless the text is personal. On `Salvesta` the chosen AI picture is stored with `/next/symbol-generate/save` and set as the card's `image`; a toast says when it was shared.
  - The search never shows another customer's own pictures; only the shared library is common.
  - In `/boards/[id]/edit`, if there are unsaved changes, leaving the page must require explicit confirmation.
  - The unsaved-changes guard must apply to both anchor navigation and forms marked with `data-navigation-form` (e.g. parent/child mode switch flows).
  - `Lisa plokk` text-based bulk add must support both one-line-per-card input and sentence paste with an editable split preview.
  - In bulk add, prefer the member's own picture whose alt text or file name is exactly the word, then such a picture in the media library (admin folders before the `AI-pildid` folder), before falling back to ARASAAC (see `symbols-ai.md`).
  - In bulk add, if the direct local/ARASAAC lookup finds no image, use `/next/groq` to generate a small ordered set of English ARASAAC search terms and try each term until the first image is found.
  - When bulk add finds images through Groq-generated ARASAAC terms, show a Sonner info toast listing the original text and matched English search term.
  - The `Lisa plokk` dialog must stay within the viewport and scroll internally when the form or sentence preview is long.
  - Explicit board saves must show visible progress while the save request is in flight.
  - The editor saves with `PATCH /api/boards/<id>?depth=0`: it doesn't read the answer, and at the default depth Payload fills every card's media.
  - Saving board grid changes must regenerate missing cached TTS audio for current cell labels.
  - Saving compounds must regenerate missing cached TTS audio for compound speech forms.
  - In `/boards/[id]/edit`, editor grid row height should track the column width so 1x1 editable cells render as square tiles.
  - In `/boards/[id]/edit`, mobile layouts should start at 3 columns and increase at wider breakpoints.
  - Editor cell controls (move grip, `Muuda kaarti`, `Kustuta kaart`, resize corner) are all 28px with 8px corners (`rounded-[0.5rem]`; the theme's `rounded-lg` is `--radius`, 3.2px) and sit 8px from the cell's edges, the cell's padding; in cells under 112px wide they move to 4px (a container query in `globals.css`), so they fit at the 96px minimum. The grip and the resize corner are bare marks with a grey hover background, so the corner doesn't cover the label; edit and delete are filled buttons. The resize corner is styled in `globals.css` (`.board-editor-grid`), replacing react-resizable's corner mark. A cell without a picture keeps its label below the controls.
  - While a cell is dragged or resized, the drop area is a dashed box with the cards' corners in the logo's blue (`.react-grid-placeholder` in `globals.css`, replacing react-grid-layout's pink box), and the moving card lifts above it with a deeper shadow.
- Home page rules:
  - Show board content and connect-dots content in separate top-level sections.
  - Within each top-level section, owned items and shared items may render as separate subsections.
  - Owned items use document-level `pinned` and `order`.
  - Shared items (`visibleToAllUsers`) are shown on `/kodu` by default for every user unless that user hides them.
  - Shared item hide/show and order are stored per user, not on the shared document itself.
  - Reordering is parent-mode only within each rendered subsection.
  - Reordering moves the cards at once and saves in the background (`reorderMixedBoards`, `reorderMixedPuzzles`): one query finds the owners of the cards, and the order updates return nothing populated (`depth: 0`).
  - The trash button on a home card (parent view) removes it from the home at once (`useOptimistic` in `SortableBoards` and `SortableConnectDotsPuzzles`) and saves in the background. The actions return an `ActionResult` and revalidate `/kodu` and `/koduhaldus`; the success toast comes when the save returns, and a failed save brings the card back with an error toast.
  - Enter or Space on a card's own buttons and links (drag handle, edit, remove) acts on them; only on the card itself does it open the board or game.
  - Parent mode must expose both actions on `/kodu`: `Lisa uus tahvel` and `Halda koduhaldust`.
  - `/kodu` loads its four lists (own and shared boards and games) at once, with `pagination: false` (Payload's default stops at 10). Boards load only what a card shows (`HOME_BOARD_SELECT`: name, order and the cards' pictures), so the browser gets no owner documents, other cards or speech cache.
  - `/kodu` and `/koduhaldus` read the user with `getCurrentUser`, which React's `cache` shares with the header, so a page render authenticates once.
- Board runner rules:
  - On `/boards/[id]`, the board shows its own columns while a tile is at least 96px wide (`MIN_TILE_WIDTH`, the editor's minimum too), and always from a 1024px grid: an upright iPad shows a six-column board as the parent made it, with every word in its place. Below that it shows a rearranged copy with at most 4 columns from a 768px grid and 3 below, in reading order (row by row, each tile into the shortest column), so the words keep the board's order. Never clamp tiles into fewer columns in place: tiles from the cut columns were pushed to the bottom of the board.
  - The runner grid takes its `width` from its own ResizeObserver, not `WidthProvider`, and renders once that width is known, so the columns, tile width and square row height come from the same number when the device turns.
  - On `/boards/[id]`, board runner grid row height should track the active column width so 1x1 board items render as square tiles.
  - Board card labels should sit below the image without a background overlay, use black uppercase text, and leave enough card space so images and labels do not overlap.
  - Labels never break a word (`CellLabel` in `boards/[id]/CellLabel.tsx`, used by the runner and the editor): the font shrinks from 1.25rem down to 0.625rem until the label's longest word fits the cell, using the cell's full inner width. A 15-letter compound still fits a 390px phone's 3-column board; a longer one is hyphenated where the browser knows Estonian, and only then broken.
  - AAC board runner tiles should have high-visibility hover/press affordances: clear border/ring contrast, obvious lift on pointer hover, and a readable pressed state without adding extra hover box shadow.
  - A tile with a word class (and the board's colours on) has a 4px border in the class colour, and its pressed and hover rings are that colour, lighter: the orange of the other tiles' rings is the colour of things. A word in the phrase bar has a border in its card's class colour.
  - Tile hover styles apply only where a pointer hovers (`[@media(hover:hover)]:hover:`): a touch screen keeps `:hover` on the last tapped tile, which then stayed orange as if it were still speaking.
  - The board runner action bar should stay fixed at the bottom of the viewport, remain compact enough for child-mode play, and leave bottom padding so board tiles are not hidden behind it. The padding follows the bar's measured height (ResizeObserver): on phones the phrase sits above the buttons, and iPhones add the home indicator's safe area.
  - In child mode, `/boards/[id]` must include minimal in-page controls for returning to `/kodu` and opening the parent PIN dialog because global header navigation is hidden.
  - A card that opens another board (`linkBoard`, a board the user can read: the page looks them up with `overrideAccess: false`, so one that is gone or private to someone else is an ordinary card) has a folder mark in its corner and the name `<word>, avab tahvli <board>`. A tap opens `/boards/<id>?from=<this board>` without saying or adding the word, and hands the sentence over (`sessionStorage`, addressed to that board, taken within a minute): the sentence goes on there, its words keeping their pictures and classes, and the word forms run over all of it. With `from`, the child bar (and the parent view's header) has a back button, `Tagasi: <board>`, which hands the sentence back. A board opened from the home or by URL starts with an empty sentence.
  - The action bar holds only the child's controls (phrase, play, undo, clear), in both views, so the parent view shows the board the way the child gets it. The runner uses the board's saved AI setting (`extra.ai`); AI and compounds are set in the editor, not in the runner.
  - With the AI setting on, a tap never waits for the AI: the word is said at once (as written, or in its word form, from the speech cache), and `/next/groq` is asked for its form from the two words before it as the sentence says them. The answer replaces the word in the phrase and "play all", and on its tile while the tile still shows the word; an undone or cleared word is left alone (each tap has its own key). The sentence for "play all" is fetched ahead only once the AI's forms are in. The first word and a word the word forms change are not sent. Waiting for the AI and then for the speech of its form made a tap take 1.5–2 s.
  - In parent mode, the board's name and, for the owner, a labelled `Muuda tahvlit` link sit above the board; a shared board says that only its creator can change it. The editor's header has `Vaata tahvlit` in the same place, so the two pages switch back and forth.
- Word form rules (`src/utilities/grammar/applyGrammar.ts`, sentences in `tests/int/grammar.int.spec.ts`):
  - A verb card in the ma-infinitive (`jooksma`, or a phrase ending in one: `hambaid pesema`), and a noun, adjective, numeral or pronoun after the verb, take the form their sentence gives them, in the tap's speech, the tapped tile, the phrase and "play all" alike. A word earlier in the sentence can change with a later tap (an adjective when its noun comes).
  - The forms are generated with Vabamorf by `scripts/grammar/generate.py`: verbs in `src/utilities/grammar/verbForms.ts` (present stem, da-infinitive, past stem, past 3rd person singular and nud-participle) from the picture bank's verbs and `scripts/grammar/verbs.txt`; the partitive of nouns (a plural noun's in the plural), adjectives and numerals in `wordForms.ts`, from every one-word picture bank word Vabamorf knows as one and the people in `scripts/grammar/words.txt`; the local cases of the places in `scripts/grammar/places.txt` (each marked `sisse`, `peale` or not a place by hand: the script stops at a bank place not listed) and of the adjectives; the comitative of the nouns, the genitive of the adjectives and numerals, the plural partitive of the nouns and adjectives, the substances in `scripts/grammar/mass.txt`, and the bank's vehicles (`VEHICLES`, its Transport words but stops and lights, and kelk, suusad, uisud). The tests fail when a bank verb, noun, adjective or place is missing. A word not in the lists stays as written. A card classed as anything but `verb` never conjugates; a card without a class does when its text ends in a listed verb. Cards classed `verb`, `question` or `social` never inflect, and neither do pronouns (they have their own object forms) or function words that are rarely a noun (`või`, `kaasa`, `liiga`, `kõik` …) unless the card is classed as a noun.
  - Within a clause (a new one starts at `sest`, `et`, `kui`, `siis` and the like, and at `ja`, `aga` or `või` after a verb, which keep the subject: "mina söön ja joon"):
    - After a subject the first verb is in the present tense of its person: nominative pronouns (`mina`/`ma` … `nemad`/`nad`), a person card (class `person`, or without a class a known person word like `ema`) in the 3rd person singular, `see`, `kes` and `keegi` too, `need` in the plural. `ja` joins subjects (`mina ja ema` → `läheme`). Two subjects without `ja`: a pronoun outranks a person, otherwise the first one counts ("mina ema kallistama" → "kallistan").
    - After `ei` the verb is in the negative (`ei jookse`, `ei ole`), with or without a subject. After `mul`, `mulle` and the like without a subject, it is in the 3rd person singular (`mul on`, `mulle meeldib`).
    - Only the first verb is finite. A verb after one of `DA_VERBS` (`tahtma`, `võima`, `saama`, `oskama` …) takes the da-infinitive (`tahan süüa`); after any other verb it stays (`pean minema`). A card that already is a form (`tahan`, `süüa`) isn't changed, but the next verb follows it.
    - A finite verb goes before the rest of a phrase card (`pesen hambaid`), an infinitive after it (`hambaid pesta`).
    - After `eile` or `üleeile` the finite verbs are in the simple past (`eile mina läksin poodi`, `eile mul oli pall`, `eile mulle meeldis joonistada`, `eile ma ei läinud kooli`, `eile ma tahtsin süüa`), after `täna`, `homme`, `ülehomme`, `praegu` or `nüüd` in the present again (the present says the future too: `homme lähen poodi`). Before the sentence's first such word, the verbs take its tense (`ma läksin eile poodi`). A card that already is a past form (`oli`, `tahtsin`) leads the next verb like a present one.
    - Without a subject or `ei` the verb stays as written. A thing is never a subject: "pall viskama" means "viskan palli".
    - After one of `OBJECT_VERBS` (`tahtma`, `sööma`, `otsima`, `kallistama` …; the last verb of a chain counts: "tahan süüa õuna"), or after any verb in a clause with `ei` or `pole`, a noun is an object, in the partitive (`tahan õuna`, `mul ei ole palli`). In the present tense the partitive is always right; the whole object ("ostan jäätise") is left out. `mängima` isn't in the list: what is played is a game or an instrument (`PLAYED`: `mängin jalgpalli`, `mängin kitarri`), anything else is played with (below). `ja`, `ning`, `või` and `ega` after an object join another one to it (`kassi ja koera`, `õuna ega banaani`) until a verb or a subject comes; after a pronoun object a pronoun is an object too (`mind ja sind`).
    - Pronouns and `see`, `too`, `need`, `keegi` as objects take their object form (`ema kallistab mind`, `tahan seda`); a person as an object is a noun (`otsin sõpra`).
    - After a counting numeral (`kaks` … `sada`, digits from 2, `mitu`, `paar`, `natuke`; not `üks`) a noun is in the partitive singular (`kaks kassi`, `natuke piima`). As part of an object the numeral takes the partitive too (`tahan kahte õuna`); otherwise it stays (`mul on kolm autot`).
    - The genitive (the comitative without its -ga, so it needs no list of its own), its adjectives and numerals in the genitive too: the noun or pronoun before one of `POSTPOSITIONS` (`kass laua peal`, `panen palli kapi sisse`, `lähen ema juurde`, `tule minu juurde`, `kingitus sinu jaoks`, `olen suure laua taga`, `lähen maja taha`; a place takes no local case there); a person or an animal (`ANIMALS`, the bank's Loomad) right before a noun, its owner (`kassi toit`, `sõbra pall`, `kassi suur kauss`, `tahan kassi toitu`, `lähen ema tuppa`, `mängin isa autoga`), and after the verb a personal pronoun (`see on minu auto`, `otsin sinu palli`). Not an owner: a pronoun before the verb (`mina pall` is "mina tahan palli"), a noun pair before a verb (`kass toit sööma` may be its subject and object), or before a noun with a postposition (`kass laua peal`).
    - After `palju`, `vähe`, `rohkem` and `vähem` a noun and its adjectives are in the partitive plural (`palju kasse`, `palju suuri õunu`, `mul on palju autosid`, `mängin palju autosid`), a substance (`MASS_NOUNS`, from `mass.txt`) in the singular (`palju vett`). The quantifier keeps its form, and the phrase takes no other case.
    - Adjectives and numerals wait for their noun and take its case (`tahan suurt punast palli`, `kaks väikest kassi`). Without a noun after them they stay as tapped (`tahan suur`), and so does a noun before the verb or after a verb that takes no object (`see on pall`, `mul on pall`, `ma ei ole kass`).
    - A place (a card classed `place`, or without a class a word of `places.txt`; a card classed as a thing never is, so `köök` from the bank's Kodu stays) takes a local case from the verb before it: where to after `MOTION_VERBS` (`lähen kooli`, `jooksen õue`, `tulen koju`, `tahan minna parki`), where from after `lahkuma` (`lahkun koolist`), where after any other verb (`olen kodus`, `mängin õues`, `söön köögis`, `ma ei ole kodus`). Each place has its own series: `sisse` (kooli, koolis, koolist) or `peale` (mänguväljakule, mänguväljakul, mänguväljakult). After `PLACE_OBJECT_VERBS` (`ehitama`, `otsima` …) the place is an object (`otsin haiglat`). It keeps its form after `mul on` (`mul on kodu`) and `see on` (`see on kool`). The adjectives before a place take its case (`lähen suurde parki`, `olen väikeses majas`); numerals stay. Only the place changes: a thing after it keeps its form (`jooksen staadionile juust`, where another AAC app said "staadionisse juustu").
    - "With" (the comitative, -ga), its adjectives and numerals in the genitive: after `mängima` anything but `PLAYED` and places (`mängin suure autoga`, `mängin kahe autoga`, `mängin klotsidega`, `mängin emaga`, `mängin sinuga`, `tahan mängida nukuga`); a vehicle after `MOTION_VERBS` (`sõidan bussiga`, `lähen kooli autoga`); one of `TOOLS` after one of `TOOL_VERBS` (`joonistan pliiatsiga`, `söön lusikaga`; `tahan lusikat` stays an object). After `koos` the next noun or pronoun (`koos emaga`, `koos sinuga`, `koos suure koeraga`); before `koos` the noun or pronoun just said after the verb (`lähen emaga koos`). After subjects `koos` is "together" and changes nothing (`mina ja ema koos läheme`).
  - Compounds apply over the word forms: a compound's word replaces the form, and a part without a word takes it. With the AI setting on, a word the rules change is said at once and only the others go to `/next/groq`, with the last two words as the sentence says them.
  - The runner and the cell modal load the word forms with a dynamic import (`useGrammar`, `loadGrammar` in `src/utilities/grammar/useGrammar.ts`), never `applyGrammar` directly: the word lists (about 30 kB gzipped) are a chunk of their own, loaded after the board shows, so they don't hold up the page. A tap before they are in waits for them; the phrase takes its forms once they arrive. The server (the speech cache) imports `applyGrammar` as usual.
  - The board setting `extra.grammar` (`Lisaseaded` → `Sõnavormid lauses sees/väljas`) turns them off. It is on by default, for boards from before it too.
  - Speech: a save adds the forms the board's sentences can need to `ttsCache` (`source: 'grammar'`, `boardWordForms`): each verb card in the persons of the board's subject cards (and their plurals with a `ja` card), in the negative with an `ei` card and in the da-infinitive with a card of `DA_VERBS`, and in the past too with an `eile` card; each noun and adjective card in the partitive with a card of `OBJECT_VERBS`, `ei` or a counting numeral; each place card where to, where and where from as its verbs call for them; its nouns, pronouns and adjectives with -ga after `mängima` or `koos`, its vehicles after a verb of motion and its tools after what they are for; its nouns and adjectives in the partitive plural with `palju`; its nouns, pronouns and adjectives in the genitive with a postposition (an owner, `kassi toit`, is synthesized when said); its pronouns and numerals as objects. At most `GRAMMAR_SPEECH_MAX`, the most used first. The save looks up only forms new to the manifest. The runner preloads the cards and compounds when the board opens, and after each tap up to 24 forms the next tap can need (after `mina` each verb card's 1st person, after `tahan` each noun's partitive). A form not in the manifest is synthesized on demand like any unsaved speech.
- Compound rules (`/boards/[id]/compounds`, owner-only, parent mode):
  - A compound is a run of at least 2 cells with a word, and optionally a speech form, for each cell: `kaks` + `kass` → "kaks kassi". The matching is in `compounds/applyCompounds.ts` and `compounds/getCompoundFormForLastToken.ts`, with tests in `tests/int/board-compounds.int.spec.ts`. The editor and the save action check compounds with the same `compounds/validateCompounds.ts`.
  - When compounds overlap, the longer one sets a word's form; between two of the same length, the earlier one in the list.
  - A tapped word that completes a compound is said in the form the whole phrase gives it (the tap takes it from `applyCompounds`), so the tap and "play all" agree. The phrase bar shows the same forms. The tapped tile shows the written form, never the speech form.
  - A compound the child has started also changes words: once its first two or more cells are the last words tapped, those words take its forms (`poiss` + `mängima` says and shows "poiss mängib" before `korvpall` is tapped), in the tap, the phrase and "play all" alike. One word doesn't start a compound, so a word never changes form only because a compound begins with it. If the sentence goes another way, the words are as tapped again. Words of a whole compound keep its forms.
  - Compounds are off when the board's AI setting is on.
  - The page (`compounds/CompoundsEditor.tsx`, `compounds/CardPicker.tsx`) speaks the parent's language: cards (`kaart`, as in the board editor), words (`Sõna`) and pronunciation (`Hääldus`), never "cell", "TTS" or IDs.
    - Each compound is a card that says what it does: the cards' pictures and words, then the words it says (`KAKS + KASS → kaks kassi`), with `Kuula` (the whole compound through `/next/tts-ms`) and delete (undo in the toast). Opened, it has a row per card: the card, its word and, behind `Hääldus erineb kirjapildist`, its pronunciation. An empty pronunciation says the word, so the speech follows the word while it's edited; the editor drops saved pronunciations that only repeat the word.
    - Cards are picked from the board's own cards with their pictures (`CardPicker`, in reading order, with a search from 13 cards). A new compound is made by tapping cards in the order the child taps them; a row's card is swapped, or a card added, with one tap. A compound keeps at least two cards.
    - Save sits in a bar at the bottom of the screen: `Salvesta` while there are changes, `Salvestatud` without, disabled until the save returns. A failed save opens the first compound that needs fixing and marks its empty word. Leaving with unsaved changes asks first (`useUnsavedChangesGuard`).
    - A compound with a card that was removed from the board is marked `Kaart on kustutatud` (it can never match). A board with AI on, or without cards, says so above the list.
    - The save action returns an `ActionResult`, so its messages reach the page in production, and updates with `overrideAccess: false`. Tested in `tests/int/compounds-editor.int.spec.tsx` and the member flow e2e test.
  - The board editor's `Sõnaühendid` button shows how many compounds the board has.
- Boards management rules:
  - `/koduhaldus` must include a separate connect-dots puzzles table.
  - Non-admin users must see their own rows plus rows shared via `visibleToAllUsers`.
  - The puzzles table must indicate that rows are connect-dots games.

  - The editor shows the board's own columns while a cell is at least 96px wide (`MIN_CELL_WIDTH`), and a rearranged copy with fewer columns below that. In that copy, moving and resizing are off and layout changes are ignored: mapping them back to the board's columns widened and moved every cell. Never write a scaled layout back to the board.
